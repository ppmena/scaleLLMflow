\section{Package scaleLLMflow}
\index{scaleLLMflow-package}

\subsection{Description}
Reusable helpers for registering scientific quality scales, resolving prompts by
provider and model, sending article text to Gemini, OpenAI, or Claude, validating strict JSON responses,
parsing item scores, comparing them with reviewed references, and writing audit
and evidence files.

The package deliberately separates three layers: the formal scale definition in
metadata, the operational prompt sent to the model, and the numeric coding used
for analysis. The bundled MQS and PEDro registries provide provider-generic
prompts for Gemini, OpenAI, and Claude, plus selected model-specific variants.

\subsection{Two workflow modes}
\begin{description}
\item[Free mode] The model response is scored and preserved for inspection without
assuming that a previous answer is correct.
\item[Reference mode] A reviewed score vector is supplied and every returned item
is compared with it. This mode reports agreement and mismatches while preserving
the model's evidence and reasoning.
\end{description}

\subsection{Credentials and provider configuration}
Gemini credentials are read from \code{GEMINI_API_KEY} or \code{GOOGLE_GEMINI_KEY}.
OpenAI credentials are read from \code{OPENAI_API_KEY}; \code{OPENAI_PROJECT_ID}
may also be supplied. A project-level \code{.Renviron} file is convenient for
interactive work in RStudio and should not be committed.
Claude credentials are read from \code{ANTHROPIC_API_KEY} or
\code{CLAUDE_API_KEY}.

\section{Registry and scale helpers}

\function{available\_scales}
\manualpart{Description}Lists scales available in the prompt registry.
\manualpart{Arguments}\begin{description}
\argitem{registry_dir}{Optional registry root. The bundled registry is used when omitted.}
\end{description}
\manualpart{Value}A character vector of scale identifiers.

\function{available\_provider\_models}
\manualpart{Description}Queries the provider's live model catalogue. This function
is independent of the scale registry and does not use hard-coded model lists.
\manualpart{Arguments}\begin{description}
\argitem{provider}{\code{gemini}, \code{openai}, \code{claude}, or an alias. The aliases \code{chatgpt} and \code{anthropic} are accepted where applicable.}
\argitem{api_key}{Optional in-memory key. Otherwise the provider environment variables are used.}
\argitem{timeout}{Request timeout in seconds.}
\argitem{supported_only}{For Gemini, retain models supporting \code{generateContent}.}
\end{description}
\manualpart{Value}A data frame with provider, model identifier, and display name.
OpenAI uses \code{OPENAI_API_KEY}; Gemini uses \code{GEMINI_API_KEY} or
\code{GOOGLE_GEMINI_KEY}; Claude uses \code{ANTHROPIC_API_KEY} or
\code{CLAUDE_API_KEY}.

\function{resolve\_prompt}
\manualpart{Description}Resolves the most appropriate registered prompt and its
metadata. Matching proceeds from the exact model to family, numeric-version,
provider-specific generic, generic, and nearest available fallbacks. The
provider-specific fallback folders are named \code{claude-generic},
\code{gemini-generic}, and \code{openai-generic}.
\manualpart{Arguments}\begin{description}
\argitem{scale}{Scale identifier.}\argitem{model}{Requested model identifier.}\argitem{provider}{Optional provider used to select its generic prompt.}\argitem{registry_dir}{Optional registry root.}
\end{description}
\manualpart{Value}A resolved registry record containing prompt text, metadata,
scale definition, response schema, and provenance fields.

\function{audit\_model\_registry}
\manualpart{Description}Checks every scale and model registry entry for required
files, valid metadata, a complete item definition, a coherent response schema,
and prompt hashes. Exact duplicate prompts are grouped and a unification plan is
reported.
\manualpart{Arguments}\begin{description}
\argitem{registry_dir}{Optional registry root.}\argitem{output_dir}{Optional directory for audit CSV reports.}\argitem{apply_unifications}{If \code{TRUE}, moves redundant prompt folders to a timestamped backup after reporting the plan.}
\end{description}
\manualpart{Value}An audit result with issue and success counts, duplicate groups,
and proposed or applied unifications.

\section{Prompt and text preparation}

\function{build\_scale\_prompt}
\manualpart{Description}Combines an operational scale prompt with the article text.
\manualpart{Arguments}\begin{description}
\argitem{prompt_text}{Registered prompt text.}\argitem{article_text}{Article text to evaluate.}
\end{description}
\manualpart{Value}The complete provider prompt as a character string.

\function{extract\_article\_text}
\manualpart{Description}Reads local Markdown or text articles and optionally removes
the references section. PDF input is supported through \code{extract_pdf_text}.
For PDF articles, \code{conversion = "llm"} generally produces better reading
order and Markdown structure, especially for multi-column articles.
\manualpart{Arguments}\begin{description}
\argitem{file_path}{Local article path.}\argitem{filetype}{One of \code{auto}, \code{txt}, \code{md}, or \code{pdf}.}\argitem{strip_references}{Whether to remove references before model submission.}
\end{description}
\manualpart{Value}Article text.

\function{extract\_pdf\_text}
\manualpart{Description}Extracts text from a local PDF using \code{pdftools}. With
\code{conversion = "llm"}, an LLM reconstructs reading order and Markdown structure;
this generally gives better results for complex and multi-column articles.
\manualpart{Arguments}\begin{description}\argitem{pdf_path}{Local PDF path.}\argitem{strip_references}{Whether to remove references.}\end{description}
\manualpart{Value}Article text.

\function{convert\_article\_markdown\_llm}
\manualpart{Description}Converts extracted article text into faithful Markdown
with an LLM, reconstructing reading order, headings, and clearly identified tables.
This generally improves results for complex PDF layouts.
\manualpart{Value}Markdown text returned by the configured provider.

\function{strip\_references\_section}
\manualpart{Description}Removes a detected references or bibliography section.
\manualpart{Value}Text with the trailing references section removed when detected.

\section{Parsing and provider calls}

\function{parse\_scale\_scores}
\manualpart{Description}Validates and parses a strict JSON scale response. Fenced
JSON is normalized in a controlled way before validation. The registered metadata
defines required items, allowed values, excluded items, and total-score rules.
\manualpart{Arguments}\begin{description}
\argitem{text}{Raw model response.}\argitem{items}{Expected item identifiers.}\argitem{metadata}{Optional resolved metadata and JSON Schema.}
\end{description}
\manualpart{Value}A named numeric vector of item scores. When metadata is supplied,
the response is validated against its declared schema before scores are returned.

\function{run\_llm}
\manualpart{Description}Calls Gemini through the Interactions API, OpenAI
through the Responses API, or Claude through Anthropic's Messages API. It applies rate limiting, retries transient failures
with exponential backoff, records detailed errors, and returns the raw response
needed for auditability.
\manualpart{Arguments}\begin{description}
\argitem{prompt}{Prompt sent to the provider.}\argitem{provider}{\code{gemini}, \code{openai}, \code{chatgpt}, \code{claude}, or \code{anthropic}.}\argitem{model}{Provider model identifier.}\argitem{temperature}{Sampling temperature; zero is recommended for reproducibility.}\argitem{top_p}{Gemini nucleus sampling parameter; ignored by OpenAI and Claude.}\argitem{timeout}{Timeout per attempt, in seconds.}\argitem{api_key}{Optional in-memory API key.}\argitem{project_id}{Optional OpenAI project id.}\argitem{max_retries}{Maximum transient-failure retries.}\argitem{retry_wait_seconds}{Initial retry delay.}\argitem{retry_backoff}{Retry-delay multiplier.}\argitem{rate_limit_seconds}{Minimum delay between requests in the current R process.}
\end{description}
\manualpart{Value}A provider response object containing text, request metadata,
model and parameter provenance, hashes, input size, and error details when relevant.

\section{Article and dataset workflows}

\function{run\_article}
\manualpart{Description}Runs one local article through a registered scale prompt.
It writes raw audit output plus convenient score and evidence CSV files.
\manualpart{Important arguments}\begin{description}
\argitem{article_path}{Local article file.}\argitem{scale}{Scale identifier.}\argitem{provider}{Provider identifier.}\argitem{model}{Model identifier.}\argitem{output_dir}{Output directory.}\argitem{reference_scores}{Named reviewed scores; activates reference validation.}\argitem{validation_mode}{\code{free} or \code{reference}.}\argitem{temperature, top_p, timeout}{Provider parameters.}\argitem{max_retries, retry_wait_seconds, retry_backoff, rate_limit_seconds}{Reliability controls.}
\end{description}
\manualpart{Value}A result containing parsed scores, totals, evidence, reasons,
validation comparisons, provenance, and output paths.

\function{run\_dataset}
\manualpart{Description}Processes all supported local articles in a directory and
consolidates scores, evidence, audit information, and errors. A semicolon-separated
reference CSV with \code{ID} and item columns activates dataset reference mode.
\manualpart{Value}A dataset result with per-article records and consolidated output paths.

\section{Bundled scales and registry layout}
The bundled registry currently contains the MQS and PEDro scales. Each provider
generic folder contains exactly two files:
\begin{verbatim}
inst/scales/<scale>/<provider>-generic/
  prompt.md
  metadata.json
\end{verbatim}
The metadata file is authoritative for item identifiers, allowed decisions,
included items, total-score rules, and the response schema. A model-specific
folder may be added only when its prompt has been separately tuned or validated.

PEDro reports all 11 items, but item 1 is excluded from the official total.
MQS uses its declared 10-item scoring definition. Do not infer a total from
the prompt text; use the metadata and package parser.

\section{Examples}
The following example is suitable for an interactive RStudio session:
\begin{verbatim}
library(scaleLLMflow)
results <- run_dataset(
  articles_dir = "examples/03_pedro_free/articles",
  scale = "pedro",
  provider = "gemini",
  model = "gemini-3.6-flash-lite",
  output_dir = "results/pedro-gemini",
  validation_mode = "free",
  temperature = 0,
  top_p = 0.1
)
\end{verbatim}

For Claude, configure \code{ANTHROPIC_API_KEY} or \code{CLAUDE_API_KEY} and
run the bundled example. The scale and model are explicitly defined in the
script:
\begin{verbatim}
Rscript examples/05_claude_free/run.R
\end{verbatim}
Edit \code{scale} and \code{model} in that script to switch between MQS/PEDro
or another Claude model.

For comparison against reviewed scores:
\begin{verbatim}
results <- run_dataset(
  articles_dir = "articles",
  scale = "mqs",
  provider = "openai",
  model = "gpt-4.1-mini",
  output_dir = "results/reference",
  reference_csv = "mqs_reference.csv",
  validation_mode = "reference"
)
\end{verbatim}
